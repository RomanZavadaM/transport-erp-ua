# ADR-0001 — Модульний моноліт

## Статус
Прийнято.

## Рішення
Для перших production-версій використовуємо **модульний моноліт**, а не мікросервісну архітектуру.

## Обґрунтування
Це зменшує операційну складність, спрощує транзакції та deployment, але дозволяє зберегти чіткі доменні межі між Fleet, Drivers, Planning, Dispatch, Release, Waybills, Maintenance, Reporting та Audit.

## Наслідки
- модулі не повинні перетворюватися на довільно зв'язаний CRUD;
- доменні межі фіксуються структурою backend;
- майбутнє винесення GPS, ticketing, payroll або інших великих контекстів у окремі сервіси залишається можливим;
- зміна цього рішення потребує нового ADR, а не переписування історії ADR-0001.
