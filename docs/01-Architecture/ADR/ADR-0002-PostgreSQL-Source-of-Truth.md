# ADR-0002 — PostgreSQL як транзакційне джерело істини

## Статус
**Superseded by ADR-0007 for architecture-v1.6.**

## Історичне рішення v1.5
PostgreSQL був визначений транзакційним джерелом істини для всієї системи та забезпечував критичні інваріанти на додаток до перевірок backend.

## Чому рішення переглянуто
Для практичного локального використання в малому АТП вимога піднімати PostgreSQL створює зайву інфраструктурну складність. Architecture-v1.6 вводить локальний встановлюваний застосунок із SQLite як оперативною БД та окремий центральний рівень, де PostgreSQL може використовуватися після передачі даних.

## Що залишається чинним
- frontend ніколи не є остаточним гарантом бізнес-цілісності;
- критичні правила перевіряє backend у транзакції;
- використовуються FK, UNIQUE, CHECK, optimistic locking та інші доступні механізми БД;
- PostgreSQL на центральному рівні може застосовувати GiST exclusion constraints, row locks, RLS та інші defense-in-depth механізми;
- Redis не є джерелом бізнес-істини.

Актуальне рішення описано в `ADR-0007-Local-SQLite-and-Central-Transfer.md`.
